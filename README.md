# شركة ايراسا — نظام إدارة مصنع الأثاث

نظام ويب لإدارة: المواد الخام والمنتجات التامة، وصفات التصنيع، أوامر الإنتاج، المشتريات والموردين، المبيعات والزبائن، المقبوضات والمدفوعات، الخزينة والمصارف، الموظفين والرواتب والسلف، المصروفات والإيرادات الأخرى، الديون، التذكيرات، التقارير الشهرية، والنسخ الاحتياطي.

- واجهة عربية من اليمين لليسار، والعملة الدينار الليبي (د.ل)، والتوقيت بتوقيت طرابلس.
- يعمل على الإنترنت عبر **Render** (الموقع، يُنشر مباشرة من مستودع GitHub) و**Neon** (قاعدة بيانات PostgreSQL)، ويُفتح من أي هاتف أو حاسوب برابط ثابت. كلاهما مجاني.
- مستخدم واحد فقط هو المالك. الموظفون سجلات بيانات فقط وليس لهم حسابات دخول.

> ⚠️ **تنبيه مهم:** تكلفة المنتج في هذه النسخة = **المواد الخام المستهلكة فعلياً فقط**. العمالة المباشرة والتكاليف غير المباشرة غير محمّلة على المنتج، لذلك «إجمالي الربح التقديري» ليس صافي ربح مدققاً.

---

## 1) النشر على الإنترنت (مرة واحدة، حوالي 10 دقائق)

### أ) قاعدة البيانات على Neon
1. ادخل https://neon.tech واختر **Sign up with GitHub** (الخطة المجانية).
2. أنشئ مشروعاً باسم `erasa` واختر المنطقة **AWS Europe Central 1 (Frankfurt)**.
3. من صفحة المشروع اضغط **Connect**، وأطفئ خيار **Connection pooling**، ثم انسخ **Connection string** (يبدأ بـ `postgresql://`). ستحتاجه في الخطوة التالية.

### ب) الموقع على Render — بنقرة من GitHub
1. ادخل https://render.com واختر **Sign up with GitHub**، واسمح لـ Render بالوصول إلى المستودع `erasa-system`.
2. اضغط هذا الرابط لإنشاء الخدمة من المستودع مباشرة:

   **[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/obairabeh2017-cyber/erasa-system)**

   (أو من لوحة Render: **New ← Blueprint** ← اختر `erasa-system`.)
3. سيطلب منك Render قيمتين فقط:
   - `DATABASE_URL`: ألصق رابط Neon من الخطوة (أ).
   - `OWNER_PASSWORD`: كلمة مرور المالك لأول دخول (8 أحرف على الأقل، أرقام وحروف).

   أما `SESSION_SECRET` و`CRON_SECRET` فيولّدها Render تلقائياً، واسم المستخدم `owner`.
4. اضغط **Apply / Deploy**. يبني Render البرنامج ويطبّق ترحيلات قاعدة البيانات (5 إلى 10 دقائق). عند الانتهاء يظهر رابط مثل:
   `https://erasa-system.onrender.com`
5. **ادخل** بالرابط باسم المستخدم `owner` وكلمة المرور التي اخترتها.
6. **غيّر كلمة المرور فوراً** من **الإعدادات ← كلمة المرور والجلسات**، ثم احذف `OWNER_PASSWORD` من Render (**Environment**).

**التحديثات:** أي تعديل يُرفع إلى فرع `main` على GitHub يُنشر تلقائياً على Render.

**ملاحظة عن الخطة المجانية:** الموقع «ينام» بعد 15 دقيقة بلا استخدام، فأول فتح بعدها يأخذ حوالي دقيقة. البيانات لا تتأثر لأنها على Neon. لإبقائه مستيقظاً يمكن الترقية لخطة Render المدفوعة (Starter)، أو استخدام خدمة مجانية مثل https://cron-job.org لفتح الرابط `https://<موقعك>/login` كل 10 دقائق خلال ساعات العمل.

**رابط مخصص (اختياري):** من **Settings ← Custom Domains** في Render يمكنك ربط نطاق تملكه مثل `app.erasa.ly`.

## 2) الأمان

- الموقع على HTTPS دائماً، وكلمة المرور مخزّنة مُشفّرة (bcrypt)، والجلسة في كعكة آمنة httpOnly.
- كل صفحة وكل إجراء حفظ يتحقق من جلسة المالك على الخادم. لا توجد صفحة تسجيل عامة.
- بعد 5 محاولات دخول خاطئة يُوقف الدخول من نفس المصدر 15 دقيقة (مسجّل في قاعدة البيانات).
- الإيصالات المرفوعة محفوظة داخل قاعدة البيانات ولا تُعرض إلا للمالك بعد الدخول.
- استخدم كلمة مرور قوية لا تستخدمها في مكان آخر، وفعّل التحقق بخطوتين على حسابات GitHub وRender وNeon.

**نسيت كلمة المرور؟** من لوحة Neon افتح **Tables ← OwnerSettings** واحذف الصف، ثم ضع `OWNER_PASSWORD` جديدة في Render (**Environment**) وانتظر إعادة التشغيل، وادخل بها. أو من حاسوب فيه البرنامج: ضع رابط Neon في `.env` ونفّذ `npm run owner:set`.

## 3) النسخ الاحتياطي والاستعادة

- **تنزيل نسخة كاملة:** الإعدادات ← **«تنزيل نسخة احتياطية كاملة»**. يُنزّل ملف JSON يضم كل البيانات والإيصالات. **نزّله أسبوعياً على الأقل** واحفظه على جهازك أو ذاكرة USB.
- **نقاط استعادة Neon:** لوحة Neon تتيح الرجوع بالقاعدة إلى وقت سابق (المدة حسب الخطة).
- **الاستعادة من ملف** (من حاسوب فيه البرنامج، مع ضبط `.env` على القاعدة المطلوبة):
  ```bat
  npm run db:restore -- erasa-backup-20261018-060000.json --replace
  ```
  تتم الاستعادة في معاملة واحدة: إن فشل أي جزء لا يتغير شيء. بعدها يُتحقق من عدد السجلات في كل جدول وسلامة أرصدة المخزون.

## 4) المهام التلقائية والتذكيرات

- ما دام الموقع يعمل، يولّد البرنامج كل 30 دقيقة التذكيرات (ديون، رواتب، مصروفات دورية، مخزون منخفض) ويحفظ تقرير الشهر المنتهي، دون تكرار.
- تُحدَّث التذكيرات أيضاً عند كل فتح للبرنامج إن مرّت ساعة على آخر تحديث، فلا تفوتك حتى لو كان الموقع نائماً. التذكيرات تبقى ظاهرة داخل البرنامج حتى تُنهيها.

## 5) التصدير والطباعة

- كل قائمة رئيسية فيها زر **تصدير CSV** (يفتح في Excel بالعربية بشكل صحيح)، وكل أنواع التصدير في صفحة الإعدادات.
- الفاتورة والتقارير: زر **طباعة / حفظ PDF** ثم «حفظ كـ PDF» في نافذة الطباعة.

## 6) قواعد العمل المهمة

- المخزون لا يُعدّل مباشرة أبداً: كل تغيير حركة مسجّلة (رصيد افتتاحي، شراء، استهلاك إنتاج، إنتاج، بيع، مرتجع، تسوية). الرصيد السالب ممنوع، والطلبات المتزامنة تُسلسل بقفل على مستوى قاعدة البيانات.
- **المسودة** لا تؤثر على المخزون أو الأرقام. **الترحيل** نهائي ولا يتكرر. التصحيح يكون **بالإلغاء** (حركات عكسية مع سبب في سجل التدقيق) أو بالمرتجع.
- إكمال أمر الإنتاج يتم في معاملة واحدة: يخصم المواد ويضيف المنتج ويحسب التكلفة، وإن فشل أي جزء لا يتغير شيء.
- تكلفة المواد بطريقة **المتوسط المرجّح**، وتُحفظ لقطة منها في كل فاتورة بيع حتى لا يتغير الربح التاريخي.
- المبيعات ≠ المقبوضات، والمشتريات ≠ المصروفات، والرصيد النقدي ≠ الربح.
- السلفة ليست مصروفاً. مصروف الرواتب = الراتب المستحق + المكافآت − الخصومات، ويُحتسب مرة واحدة.

## 7) التشغيل على جهاز محلي (اختياري، للتطوير أو الطوارئ)

يتطلب Node.js 22 LTS. انسخ `.env.example` إلى `.env` وضع فيه روابط قاعدة Neon، ثم:

```bat
npm install
npm run setup
npm run build
npm start
```

أو انقر مرتين على `start.bat`. البرنامج يعمل على `http://localhost:3000`، ويحفظ نسخة احتياطية تلقائية في مجلد `backups` كل 24 ساعة ما دام يعمل.

## 8) أوامر مفيدة

| الأمر | الوظيفة |
|---|---|
| `npm run setup` | تطبيق الترحيلات وتهيئة القوائم الافتراضية |
| `npm run owner:set` | إنشاء حساب المالك أو تغيير كلمة المرور |
| `npm run db:migrate` / `db:status` | تطبيق الترحيلات / فحص حالتها |
| `npm run db:backup` | حفظ نسخة احتياطية JSON في مجلد `backups` |
| `npm run db:restore -- <ملف> [--replace]` | استعادة نسخة احتياطية |
| `npm test` | الاختبارات الآلية (على PostgreSQL محلي داخل الذاكرة، لا تحتاج اتصالاً) |
| `npm run check` | فحص الأنواع + التدقيق + الاختبارات |

## 9) حل المشكلات

- **فشل النشر على Render:** افتح الخدمة ← **Events** أو **Logs**. إن ظهرت رسالة «لا يوجد رابط قاعدة بيانات PostgreSQL» فضع رابط Neon في `DATABASE_URL` (Environment) ثم **Manual Deploy**.
- **«لم يتم إعداد حساب المالك بعد»:** ضع `OWNER_USERNAME` و`OWNER_PASSWORD` في Render (Environment) ثم انتظر إعادة التشغيل.
- **الموقع بطيء في أول فتح:** طبيعي في الخطة المجانية (الموقع كان نائماً). انتظر دقيقة.
- **رفع الإيصال يفشل:** الحد الأقصى 4 ميغابايت؛ صوّر الإيصال بدقة أقل.
- **فحص سلامة البيانات:** الإعدادات ← «تشغيل الفحص» يطابق كل رصيد مخزني مع مجموع حركاته.

## 10) ما ليس موجوداً في هذه النسخة (مخطط لاحقاً)

- تحميل تكلفة العمالة والتكاليف غير المباشرة على المنتج.
- الإشعارات الخارجية (SMS/واتساب/بريد). التذكيرات حالياً داخل البرنامج فقط.
- مرتجعات المشتريات للموردين: التصحيح حالياً بإلغاء فاتورة الشراء كاملة (إن لم تُستهلك كمياتها).
- نسخ احتياطي تلقائي إلى تخزين خارجي على الاستضافة السحابية: حالياً بالتنزيل اليدوي + نقاط استعادة Neon.

## 11) للمطورين

Next.js 15 (App Router) + TypeScript + Tailwind CSS 4 + Prisma 6 + PostgreSQL (Neon). المال أعداد صحيحة بالدرهم (1 د.ل = 1000)، والكميات بالألف من الوحدة، بدون أعداد عشرية عائمة. منطق العمل في `src/lib/services`، والاختبارات في `tests/` وتعمل على PGlite (PostgreSQL داخل الذاكرة) بنفس ملفات الترحيل.
